# DX2SDK v0.8.0: Public Deus Ex: Invisible War Python SDK

**Status:** usable source-backed Python toolkit and experimental native
StaticMeshActor translation-only Save As. This is **not** the complete original
UnrealEd/T3Ed editor and is **not** a validated retail mission compiler.

The SDK packages existing DX2Ed reverse engineering into one documented,
reusable API plus a source-only command-line entry point. It builds on the
original DX2 v95 Unreal package reader, T3SDK's byte-identical roundtrip
support, and a narrowly limited source-pinned Location writer.

No original Deus Ex: Invisible War game files are included. Bring your own
legally obtained retail `.gmp`, `.ibd`, `TriggerScript.zip` and, where
needed, DX2Ed-generated private `actors.json` for that exact GMP.

## Standalone DX2SDK portable ZIP (no Godot needed)

The SDK is also distributed as a separate **`DX2SDK_Python_v0_8_Portable`**
GitHub Actions artifact, generated by
`tools/build_dx2sdk_source_release.py`. This ZIP contains only the
public `dx2sdk/` Python package, its required open-source DX2Ed package
readers and restricted native writer, MIT T3SDK source/format metadata
and license, and this README. It contains **no** Godot executable, game
binary, retail map, texture or script bundle.

Extract the ZIP's inner `DX2SDK_Python_0.8.0.zip`, then on Windows run
`RUN_DX2SDK.cmd --help`. You need Python **3.11+** installed but do not
need Godot or DX2Ed's GUI launcher. Linux/macOS users can run
`python3 -B -m dx2sdk --help` from the extracted SDK root.

The standalone archive includes a per-file SHA-256
`sdk-manifest.json` and is smoke-tested by GitHub Actions on both
Linux and Windows. The GitHub Actions download itself expires at the
artifact retention limit; **copies you download do not expire**.

## v0.8: reusable 2–8 actor LightColor project plans

A private `DX2SDK-source-multi-LightColor-plan-v1` JSON now captures
**two to eight separate original placed actors** and exact original
brightness/hue/saturation bytes. This edits existing authored blocks,
not lighting archetype defaults, scripts, IBD assets, geometry or native
new-Light actors.

The portable console needs only the original GMP and Python 3.11+:

```bat
RUN_DX2SDK.cmd make-lightcolor-plan --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp" --edit 426 96 150 32 255 0 255 --edit 1989 96 150 32 255 0 255 --plan "D:\SDKResearch\PrivatePlans\red-lights.json"
RUN_DX2SDK.cmd apply-lightcolor-plan --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp" --plan "D:\SDKResearch\PrivatePlans\red-lights.json" --output "D:\SDKResearch\Isolated\M1_Seattle_Hub_WTOterminal.gmp"
RUN_DX2SDK.cmd verify-multi-lightcolor --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp" --output "D:\SDKResearch\Isolated\M1_Seattle_Hub_WTOterminal.gmp"
```

Each `--edit EXPORT OLD_B OLD_H OLD_S NEW_B NEW_H NEW_S` pins the exact
original actor and all three existing source bytes. At least one new
value for each actor must actually differ. Repeat 2–8 times; every
export must be unique and its pre-existing 10-byte LightColor struct
must pass both independent parsers. The SDK derives native actor names
from the verified original export table, never from a new arbitrary
class or actor name. The example ids/values correspond to original
WTO Terminal research, not a universal map compatibility claim.

`make-lightcolor-plan` only writes a **fresh private JSON**, not a GMP.
`apply-lightcolor-plan` defaults to **in-memory dry run**; add
`--write` to create one isolated same-basename GMP and a separate
`.dx2sdk-multi-lightcolor.json` verifier. The independent writer
must match all approved original source byte offsets across the **full
GMP**, preserve tables/GUID and leave every other byte alone. The
verifier replays every change from the still-unchanged source and
rejects unauthorized output, tampered plan identities or forged
runtime support flags. Game Maps destinations, existing outputs and
overwrites are refused.

Python: `DX2Map.build_lightcolor_plan(edits)`,
`DX2Map.write_lightcolor_plan(edits, json_path)`,
`DX2Map.load_lightcolor_plan(json_path)`,
`DX2Map.apply_lightcolor_plan(json_path, isolated_gmp, write=False)`,
`DX2Map.verify_saved_multi_lightcolor(isolated_gmp)`.

**Scope remains experimental.** The 2–8 source batch is not proof
of retail runtime validity or color falloff. Creating new native
Light actors requires reliable point-to-BSP-leaf/zone ownership and
state-frame initialization; neither is available. No new light
creation, light baking, BSP/CSG or physics regeneration is enabled.

## v0.7: existing authored GameSys LightColor byte editing

The native GameSys property **116 / LightColor** is a struct containing
three individually tagged source-byte fields: `LightBrightness`,
`LightHue`, and `LightSaturation`. This SDK release adds a **very limited
experimental writer** for only a *pre-existing* original actor block with
the exact source-researched 10-byte layout and property names. Actor
class is **not** inferred from display name: the block may be authored
on a fixture (`D_298`) as well as a native `Light`.

Use original GMP bytes from your own installation. The commands work
without Godot or a previously imported `actors.json`:

```bat
RUN_DX2SDK.cmd light-colors --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp" --limit 50

RUN_DX2SDK.cmd set-light-color --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp" --actor "D_298__4" --export 426 --expect 96 150 32 --brightness 255 --hue 0 --saturation 255 --output "D:\SDKResearch\Color\M1_Seattle_Hub_WTOterminal.gmp"

RUN_DX2SDK.cmd verify-light-color --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp" --output "D:\SDKResearch\Color\M1_Seattle_Hub_WTOterminal.gmp"
```

The `set-light-color` command is **dry-run by default**. Append
`--write` to create the isolated GMP and
`.dx2sdk-lightcolor.json` manifest. At least one of `--brightness`,
`--hue`, `--saturation` is required. Every value must be an integer
from 0 through 255 and must differ from the actual original source byte.
The required `--expect B H S` pins all three **original** byte values
before any modification. The example source/export and values reflect
the original WTO Terminal research; the SDK verifies them rather than
assuming any installation has the same map.

The writer requires two independent original actor readers to agree on
native export/name/class, Level-position membership, block version,
non-runtime flag, and the *exact* nested tag names, byte tags, order,
terminator and 10-byte length. It first proves an **exact** original
T3SDK no-op package rewrite. Every proposed output must then agree
between T3SDK's structured ActorEdit writer and the independent
DX2 source-offset patch across **every byte** of the GMP. No name,
import, export, GUID, BSP, script, mesh, collision or package size
changes are authorized.

After explicit writing, `verify-light-color` reconstructs that entire
GMP from its unchanged original and refuses modified field offsets,
added bytes, source map drift, forged hashes or false runtime claims.
Outputs cannot overwrite existing files or target any
`Content/DX2/Maps` folder.

**Retail evidence, carefully scoped:** Earlier project research documents
user-reported color/brightness effects after correcting a game content-root
issue, including red light from a four-fixture color candidate. Those
reports do **not** prove a single-actor edit, hue mapping at all values,
repeatable runtime behavior in all maps, or a general engine light editor.
The source-only SDK tests prove serialization parity, not rendering.
No new `Light` actor, `Region.iLeaf`/`ZoneNumberLow` assignment, light
bake or BSP collision regeneration is provided. Keep this feature
experimental and do not write into live game Maps directories.

Python API:
`DX2Map.original_light_colors(limit=50)`,
`DX2Map.set_existing_light_color(export=426, actor="D_298__4",
expected=(96,150,32), changes={"brightness":255,"saturation":255},
output=path, write=False)`, and
`DX2Map.verify_saved_light_color(path)`.

## Original Light audits and existing bLightOn editing (v0.6)

DX2SDK now exposes the prior source-only Light dependency inspector and
a deliberately restricted existing GameSys Boolean editing workflow without
Godot or an `actors.json` cache.

- `audit-lights` checks native Light actor class/export, Level membership,
  `Region.iLeaf`, `Region.ZoneNumberLow`, LevelInfo and PhysicsVolume
  references, and the original state frame. Add `--export` for one original
  Light or `--output` to create a new private JSON audit.
- `light-switches` lists *existing* non-runtime, one-byte authored
  `Engine.Actor.bLightOn` GameSys values (original property ID **1487**).
  These often belong to fixture actors, which are **not** necessarily native
  `Light` actors.
- `set-light-switch` flips only one verified existing `bLightOn` Boolean.
  It defaults to an in-memory **dry run**. An explicit `--write` produces
  a new isolated same-basename GMP and a separate verification manifest.
- `verify-light-switch` independently reconstructs the whole output GMP
  from the unchanged original and confirms exactly one authorized byte
  changed. A forged manifest hash cannot authorize extra changes.

Example commands from an extracted portable SDK:

```bat
RUN_DX2SDK.cmd audit-lights --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp" --export 132
RUN_DX2SDK.cmd light-switches --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp"
RUN_DX2SDK.cmd set-light-switch --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp" --actor "D_298__4" --export 426 --expect true --output "D:\SDKResearch\WTO\M1_Seattle_Hub_WTOterminal.gmp"
RUN_DX2SDK.cmd verify-light-switch --map "C:\DXIW\Content\DX2\Maps\M1_Seattle_Hub_WTOterminal.gmp" --output "D:\SDKResearch\WTO\M1_Seattle_Hub_WTOterminal.gmp"
```

The `set-light-switch` example does nothing to disk without `--write`.
Outputs cannot overwrite originals or target a retail `Content/DX2/Maps`
directory. Original-game files are not distributed.

**Limits:** no native Light spawning/relocation, region leaf/zone
recalculation, IBD edits, light baking, arbitrary GameSys field writes, or
gameplay proof. Native source bytes and dual serializer parity are checked,
but even successful runtime loading may show no visible lighting change
because existing map illumination can be baked or initialized elsewhere.
Retain these as experimental draft features until copied-install retail A/B
tests establish the effect.

Python: `DX2Map.audit_original_lights()`,
`DX2Map.export_original_lights(path)`,
`DX2Map.original_light_switches()`,
`DX2Map.set_existing_light_switch(export=426, actor="D_298__4", expected=True, output=path)`,
and `DX2Map.verify_saved_light_switch(path)`.

## Generate your own actor catalog without Godot (v0.2)

**New in DX2SDK v0.5:** you no longer need to run the Godot editor just
to obtain a source-bound `actors.json`. The SDK can scan your original
`.gmp` using the independent native actor/GameSys decoder and produce an
`actors.json` in your **private SDK workspace**.

```bat
RUN_DX2SDK.cmd scan-map --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --output "D:\\MyDX2SDKProject\\Club\\actors.json"
```

The `--output` path must be a **new** `actors.json` located outside
the retail game's `Content/DX2/Maps` tree. The SDK verifies its
source GMP SHA-256, native actor export/name/class/location identities,
rejects ambiguous native Location layouts, and reopens the generated
cache through its regular source-validation checks. Nothing is written
into the game directory.

You can optionally supply your **original** installed `System`
directory with `--system "D:\\DXIW\\System"` for original GameSys
property declarations. A compatible JSON property catalog may also
be supplied. Without it, the SDK reports numeric GameSys property IDs
and native encodings rather than inventing names.

```bat
RUN_DX2SDK.cmd inspect-actor --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --actor "StaticMeshActor__1"
RUN_DX2SDK.cmd inspect-actor --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --export 15
```

`inspect-actor` reads the actual original tagged Unreal properties
and GameSys blocks. Unsupported blocks stay explicitly opaque; their
original bytes are not copied into the console output. GameSys
TriggerScripts arrays are **not** presumed executable actor-script
bindings.

The generated private cache can immediately be passed to the
`scripts`, `ibd`, `compare`, `native-audit`, `make-plan`,
`move` and `apply-plan` commands. Source-verified native
Location changes **also require an original resolvable static-mesh
reference**. If that reference is unavailable for a particular actor,
the SDK lists it as unresolved and refuses to write it rather than
guessing a mesh or claiming safety.

### First supported native write: existing static prop translation

The SDK takes **native DX2 world X, Y, Z** (not Godot viewport coordinates).
It supports only existing `StaticMeshActor` objects whose serialized
`Location` fields and exact source actor metadata can be independently
verified. No rotation/scale or new actor spawns are serialized.

A dry run is the default:

```bat
DX2SDK_CONSOLE.cmd move --map "D:\Games\DXIW\Content\DX2\Maps\M1_Test.gmp" --actors "D:\DX2EdPrivateCache\actors.json" --actor "StaticMeshActor__1" --x 100 --y 200 --z 300 --output "D:\DX2SDK_Experiment\M1_Test.gmp"
```

To produce an **isolated, fresh copy**, append `--write` only after inspecting
the dry run. The output filename must match the original GMP. The output
directory must be outside **every** `Content/DX2/Maps` directory and
outside the original source map's tree. Existing GMP/manifest outputs are
never overwritten.

The SDK also invokes the independent full-file byte verification before
reporting `independent_binary_verification.verified_binary_structure=true`.
You can rerun that verification later:

```bat
DX2SDK_CONSOLE.cmd verify-move --map "D:\Games\DXIW\Content\DX2\Maps\M1_Test.gmp" --output "D:\DX2SDK_Experiment\M1_Test.gmp"
```

**Important:** The writer's status is intentionally
`written-unverified`. It confirms the output has the expected native
serialization and only approved original Location float fields changed,
**not** that the retail game accepts it. Test only on isolated, backed-up
game copies, with disposable saves and no original content overwritten.

## Python API

From a checkout or extracted Windows prototype root (Python 3.11+):

```python
from dx2sdk import DX2Map

source = r"D:\Games\DXIW\Content\DX2\Maps\M1_Test.gmp"
actors_json = r"D:\DX2EdPrivateCache\actors.json"

world = DX2Map.open(source)
print(world.info())
print(world.actors(actor_class="StaticMeshActor", limit=25))

# A source-matched private actors.json is mandatory for native edits.
world = DX2Map.open(source, actors_json)

# Prepare multiple existing StaticMeshActor translation-only edits:
moves = {
    "StaticMeshActor__1": (100.0, 200.0, 300.0),
}
dest = r"D:\DX2SDK_Experiment\M1_Test.gmp"

preview = world.save_as_translations(moves, dest)  # DEFAULT: dry run!
print(preview["status"])

# Only after verifying the target is a safe, unused isolated path:
written = world.save_as_translations(moves, dest, write=True)
print(written["independent_binary_verification"])
print(world.verify_saved_translation(dest))
```

The proposed coordinates must differ from the selected actor's source
coordinates. Python scripts may submit multiple distinct actors in one plan,
up to the underlying native writer's explicit bound. All basis/rotation data
are preserved from the exact source map.

### Reusable source-locked batch move projects

DX2SDK can now save a **versioned editable JSON position plan** rather
than committing a native GMP modification immediately. The plan pins
the exact original GMP SHA-256, exact DX2Ed actor-cache SHA-256, actor
export IDs, original locations and requested new native X/Y/Z.

```bat
DX2SDK_CONSOLE.cmd make-plan --map "D:\\Games\\DXIW\\Content\\DX2\\Maps\\M1_Test.gmp" --actors "D:\\DX2EdPrivateCache\\actors.json" --actor "StaticMeshActor__1" --x 125 --y 275 --z 350 --plan "D:\\DX2SDK_Experiment\\move_plan.json"
DX2SDK_CONSOLE.cmd apply-plan --map "D:\\Games\\DXIW\\Content\\DX2\\Maps\\M1_Test.gmp" --actors "D:\\DX2EdPrivateCache\\actors.json" --plan "D:\\DX2SDK_Experiment\\move_plan.json" --output "D:\\DX2SDK_Experiment\\M1_Test.gmp"
```

The second command is still a **dry run**. Append `--write` to
`apply-plan` only when you have chosen a fresh non-game output path
and want a new isolated GMP copy. The plan JSON can list multiple
existing actors, but each row's class, export number and original
location must agree with the source-authenticated cache. A stale,
modified or forged actor identity fails closed, even if the plan's
target coordinates are otherwise plausible.

Python can create multi-actor plans directly:

```python
from dx2sdk import DX2Map, write_position_plan, apply_position_plan

world = DX2Map.open(source, actors_json)
write_position_plan(world, {
    "StaticMeshActor__1": (125.0, 275.0, 350.0),
    "StaticMeshActor__2": (450.0, 160.0, 75.0),
}, r"D:\DX2SDK_Experiment\move_plan.json")

# Test first; explicit write=True required for a native output file.
print(apply_position_plan(
    world,
    r"D:\DX2SDK_Experiment\move_plan.json",
    r"D:\DX2SDK_Experiment\M1_Test.gmp",
))
```

The example names and coordinates are illustrative only; your actual
source map must contain those exact existing actors. JSON plans are
**private project files** and may include map hashes and actor names.
Don't publish them without reviewing their contents.

### Experimental native tagged numeric property editing (v0.3)

**New in DX2SDK v0.5:** A carefully restricted writer for existing,
already-serialized **top-level UE95 tagged IntProperty (int32)** and
**FloatProperty (float32)** fields on original placed
`StaticMeshActor` objects.

This is separate from GameSys scalar blocks, TriggerScript editing,
booleans, object properties, arrays, brush geometry, collision
rebuilding and rotation/scale serialization. Original source actors
must match your private `actors.json` and the unchanged GMP package.

Inspect the source actor and find eligible scalar field names first:

```bat
RUN_DX2SDK.cmd scalar-fields --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --actors "D:\\MyDX2SDKProject\\Club\\actors.json" --actor "EXACT_EXISTING_STATIC_MESH_ACTOR"
```

If the output lists a field with `type: int32` or `float32`,
you can test a proposed new value. Replace the placeholder field
and the value with an **actual source field and suitable native type**:

```bat
RUN_DX2SDK.cmd set-scalar --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --actors "D:\\MyDX2SDKProject\\Club\\actors.json" --actor "EXACT_EXISTING_STATIC_MESH_ACTOR" --property "EXISTING_NUMERIC_PROPERTY" --value 10 --output "D:\\DX2SDK_Experiment\\M1_Seattle_Club.gmp"
```

The first invocation is only a **dry run**. To create a new isolated
GMP, append `--write` after deciding on a safe, unused output
directory. A separate private `.dx2sdk-scalar.json` source-bound
manifest accompanies the result.

Recheck the output independently:

```bat
RUN_DX2SDK.cmd verify-scalar --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --actors "D:\\MyDX2SDKProject\\Club\\actors.json" --output "D:\\DX2SDK_Experiment\\M1_Seattle_Club.gmp"
```

The scalar writer enforces source SHA and native actor name/export/class/
Location consistency. It requires the **MIT T3SDK writer to reconstruct
the original GMP byte-for-byte without any changes** before proceeding,
patches only the original numeric field's four bytes, creates a fresh
copy outside **any** game Maps folder, and independently checks the
original package tables, unchanged exports and the **entire changed
byte set**. Source fields that are missing, indexed, duplicated,
opaque or outside the restricted numeric types are refused.

**Critical:** successful source-only binary verification does **not**
mean the edited property has been tested in Deus Ex: Invisible War.
This is experimental original-format editing. It is possible to
produce a byte-consistent map that the game rejects or which changes
gameplay in unintended ways. Use copies only; never overwrite your
actual installation or important saves.

Python equivalent:

```python
from dx2sdk import DX2Map

world = DX2Map.open(source, actors_json)
print(world.native_scalar_fields("EXACT_EXISTING_STATIC_MESH_ACTOR"))

draft = world.save_as_scalar_changes(
    {"EXACT_EXISTING_STATIC_MESH_ACTOR": {"EXISTING_NUMERIC_PROPERTY": 10}},
    r"D:\DX2SDK_Experiment\M1_Seattle_Club.gmp",
)  # dry run; no file created
print(draft["status"])

# Explicit opt-in to write a NEW copy, only when appropriate:
# result = world.save_as_scalar_changes(changes, output, write=True)
# print(world.verify_saved_scalar_changes(output))
```

The API also accepts multiple distinct existing numeric fields in one
source-bound edit map. A new output cannot overwrite an old Location or
scalar experiment, even if the filenames coincide.

### Experimental native duplication of an existing static prop (v0.4)

**New in DX2SDK v0.5:** You can inspect conservative **clone
candidates** and create one **new native StaticMeshActor export** by
duplicating an existing owner-original, source-verified static prop
using the MIT T3SDK/Ion Storm v95 package writer.

This is NOT arbitrary NPC spawning or a new empty actor factory. A
candidate must already be a placed `StaticMeshActor` in your original
GMP, have a fully decoded idle/neutral native state frame, contain no
object links or unknown/nonzero native tails, and pass byte-identical
source roundtrip and independent package reconstruction checks. The
original actor stays untouched; only the new export gets a neutralized
latent-action DWORD, and the Level actor list gains its new reference.

Find eligible original actors:

```bat
RUN_DX2SDK.cmd clone-candidates --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp"
```

Use the exact **source actor name and original one-based export number**
from that candidate list. The translation is a **relative native Unreal
X/Y/Z offset**, not an absolute new world position:

```bat
RUN_DX2SDK.cmd clone-prop --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --actor "EXACT_ORIGINAL_STATIC_MESH_ACTOR" --export 123 --dx 100 --dy 0 --dz 0 --output "D:\\DX2SDK_Experiment\\M1_Seattle_Club.gmp"
```

This first runs entirely **in memory**. To create a new GMP in an unused
isolated folder, explicitly append `--write`. The SDK also runs an
independent **source replay verification**, regenerating the candidate
from the original GMP and comparing **the entire saved output byte for
byte** rather than trusting only a hash or test manifest.

```bat
RUN_DX2SDK.cmd verify-clone --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --output "D:\\DX2SDK_Experiment\\M1_Seattle_Club.gmp"
```

A separate private `.dx2ed-prop-clone.json` manifest records the
source/export identities and binary verification evidence. Output
files cannot overwrite an existing GMP or be written into any game
`Content/DX2/Maps` directory. Source maps remain unchanged.

The clone has not been demonstrated to load or function in the retail
DX2 runtime; this operation also does not reconstruct BSP or
Havok/MOPP collision. It is specifically a **provenance-checked
native research writer**, not a finished T3Ed-style spawning tool.
Test eventual modified maps only in a disposable copied installation
with backups.

Python equivalent:

```python
from dx2sdk import DX2Map

world = DX2Map.open(source)
print(world.static_prop_clone_candidates(limit=100))

preview = world.clone_existing_static_prop(

)
print(preview["status"])  # in-memory only
```

### Reusable multi-prop clone plans: two to eight existing actors (v0.5)

**DX2SDK v0.5** adds source-verified cloning of **2–8 already placed,
eligible `StaticMeshActor` props** into one native GMP, using a reusable
JSON plan. This is a constrained copy of **original unlinked, state-idle
source props**, not arbitrary new actor classes or NPC spawning.

The source plan records the exact original GMP SHA-256, original actor
export and name, and the native **relative** X/Y/Z offset for each copy.
First list the source-eligible originals with `clone-candidates`, then
choose original export IDs and per-copy delta values:

```bat
RUN_DX2SDK.cmd make-multi-clone-plan --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --copy 123 100 0 0 --copy 123 0 100 0 --copy 123 0 0 100 --plan "D:\\MyDX2SDKProject\\Club\\prop_clones.json"
RUN_DX2SDK.cmd apply-multi-clone-plan --map "D:\\DXIW\\Content\\DX2\\Maps\\M1_Seattle_Club.gmp" --plan "D:\\MyDX2SDKProject\\Club\\prop_clones.json" --output "D:\\DX2SDK_Experiment\\M1_Seattle_Club.gmp"
```

## Compatibility and limits relative to T3Ed

| Editing capability | DX2SDK v0.5 |
|---|---|
| Native Ion Storm Unreal v95 GMP parsing | Implemented |
| Source-matched actor metadata and hierarchy | Implemented |
| Original script definition and IBD resource inspection | Implemented, read-only |
| T3SDK byte-identical no-op GMP reconstruction | Supported when original source passes independent parity checks |
| Native editing of existing static actor positions | Experimental isolated Save As, binary verified; retail behavior unverified |
| Existing top-level numeric tagged properties | **Experimental** existing UE95 int32/float32 fields on original static-mesh actors, isolated Save As with no-op baseline and full byte verification |
| Duplicate an original, eligible unlinked static prop | **Experimental** source-safety-checked single StaticMeshActor clone, new native export and Level reference, isolated writer and full-source replay; retail in-game load unverified |
| Original GameSys property block writing | **Not supported** by the public SDK scalar writer |
| Arbitrary native actor spawns / clones | Separate research-only probes; **not part of public API** |
| Rotation and scale native serialization | Not implemented |
| BSP / CSG brush editing and rebuilding | Not implemented |
| Havok/MOPP collision regeneration | Not implemented |
| Native TriggerScript compile/replace/assign | Not implemented |
| Conversation resource compilation | Not implemented |
| Retail game compatibility for modified maps | **Not verified by SDK tests** |

The repository's Godot editor, separate collision/source diagnostics and
T3SDK adapter remain available alongside this public API.

## Version and distribution

- **SDK API:** `DX2SDK v0.5.0`, usable from the repository, the
  Godot editor Windows prototype or the independent lightweight
  `DX2SDK_Python_0.8.0.zip`; standard-library Python 3.11+.
- **DX2Ed editor:** Godot 4.3 GUI in the same prototype ZIP, with its own
  independent feature/version development.
- **Test approach:** synthetic Ion Storm v95 package fixtures, source-hash
  spoof resistance, native writer byte range constraints, CLI invocation
  and Windows runtime package preflight.
- **Distribution:** the source-only Windows prototype includes the
  `dx2sdk/` package, launcher and the existing tested open-source readers
  and package writer. It never includes original game resources.

Planned next SDK milestones include native actor property schemas, better
roundtrip-safe native transformations, stronger original-map smoke reports,
asset placement, script-resource serialization research, and eventual
source-verified mission packaging. **Do not enable any feature as a native
writer until exact binary serialization and owner-side gameplay behavior are
independently established.**
